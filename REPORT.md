# Практическая работа: окружения и зависимости Python

## Цель работы

Цель работы — освоить создание изолированных Python-окружений, установку и фиксацию зависимостей, а также восстановление проекта на чистом окружении двумя способами:

1. `venv` + `pip` + `requirements.txt`;
2. Poetry + `pyproject.toml` + `poetry.lock`.

В качестве исходного проекта использовался скрипт `plt_temp.py`. Скрипт получает почасовую температуру Москвы через API Open-Meteo, выбирает первые 24 значения, записывает их в CSV и строит график.

## Используемая среда

Работа выполнялась на macOS на компьютере с Apple Silicon.

- Python: 3.12.14;
- Poetry: 2.5.1;
- shell: zsh;
- Python 3.12 установлен через Homebrew.

Изначально команда `python3` указывала на Python 3.14.7. Так как по условию требовался Python 3.12, он был установлен отдельно:

```bash
brew install python@3.12
```

После установки использовался интерпретатор:

```text
/opt/homebrew/bin/python3.12
```

## Часть 1. venv, pip и requirements.txt

### Создание окружения

В директории `pip_project` создано виртуальное окружение с Python 3.12:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
```

Проверка версии Python и пути к интерпретатору:

```text

$ python -c "import sys; print(sys.executable)"

```

Из пути видно, что используется интерпретатор из локальной папки `.venv` проекта, а не глобально установленный Python.

### Установка зависимостей

По импортам исходного скрипта были определены и установлены прямые зависимости:

```bash
python -m pip install requests pandas matplotlib
```

Назначение библиотек:

- `requests==2.34.2` — HTTP-запрос к Open-Meteo;
- `pandas==3.0.6` — создание таблицы и сохранение данных в CSV;
- `matplotlib==3.11.2` — построение графика температуры.

После установки программа была запущена командой:

```bash
python plt_temp.py
```

Результат запуска:

```text

```

Проверка файла `temperature_24h.csv`:

```text
Столбцы: ['time', 'temperature_c']
Строк данных: 24
```

Следовательно, программа успешно получила данные и сформировала CSV-файл с 24 почасовыми значениями температуры.

В окружении также был установлен пакет `numpy==2.5.3`. Он не является прямой зависимостью, потому что исходный скрипт не импортирует `numpy` напрямую. `numpy` был установлен как транзитивная зависимость `pandas` и `matplotlib`.

### Фиксация зависимостей

Точные версии установленных пакетов были сохранены в `requirements.txt`:

```bash
python -m pip freeze > requirements.txt
```

В файле были зафиксированы прямые и транзитивные зависимости. Например:

```text
matplotlib==3.11.2
numpy==2.5.3
pandas==3.0.6
requests==2.34.2
```

Чтобы не добавлять служебные и сгенерированные файлы в Git, был создан `.gitignore`:

```gitignore
.venv/
__pycache__/
*.py[cod]
.pytest_cache/
.ruff_cache/
temperature_24h.csv
temperature_24h.png
```

### Чистое восстановление окружения

Для проверки воспроизводимости локальное окружение было удалено:

```bash
deactivate
rm -rf .venv
```

Далее было создано новое окружение и зависимости восстановлены только из `requirements.txt`:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

После восстановления программа была повторно запущена и проверена:

```bash
python plt_temp.py
python -c "import pandas as pd; df = pd.read_csv('temperature_24h.csv'); assert list(df.columns) == ['time', 'temperature_c']; assert len(df) == 24; print('Проверка успешна:', len(df), 'строки')"
```

Результат:

```text
Сохранено в temperature_24h.csv
Проверка успешна: 24 строки
```

Таким образом, окружение `pip_project` успешно восстановилось без ручной установки отдельных библиотек.

## Часть 2. Poetry

### Инициализация проекта

Для второй части был создан отдельный каталог `poetry_project`. В него был скопирован только исходный файл `plt_temp.py`; окружение и `requirements.txt` из первой части не переносились.

Poetry был установлен отдельно как инструмент управления зависимостями. Версия Poetry:

```text
Poetry (version 2.5.1)
```

Проект был инициализирован командой:

```bash
poetry init --no-interaction --name poetry-project --python ">=3.12,<3.13"
```

В файле `pyproject.toml` задано ограничение Python:

```toml
requires-python = ">=3.12,<3.13"
```

Также в проекте был включён непакетный режим:

```toml
[tool.poetry]
package-mode = false
```

Это подходит для учебного скрипта: проект не собирается как отдельный Python-пакет, а Poetry используется для управления окружением и зависимостями.

Для создания `.venv` внутри директории проекта был добавлен файл `poetry.toml`:

```toml
[virtualenvs]
in-project = true
```

Окружение создавалось с использованием Python 3.12:

```bash
poetry env use python3.12
poetry install
```

Проверка окружения:

```text
$ poetry env info --path
/Users/waldemar/Desktop/ml-ops/practice_2/practice_2_result/poetry_project/.venv

$ poetry run python --version
Python 3.12.14

$ poetry run python -c "import sys; print(sys.executable)"
/Users/waldemar/Desktop/ml-ops/practice_2/practice_2_result/poetry_project/.venv/bin/python
```

Poetry использует локальное окружение `.venv` внутри `poetry_project` и подходящую версию Python.

### Основные зависимости и группы

Основные зависимости были добавлены командой:

```bash
poetry add requests pandas matplotlib
```

Тестовые и разработческие инструменты добавлены в отдельные группы:

```bash
poetry add --group test pytest
poetry add --group dev ruff
```

Итоговое разделение зависимостей:

- основные зависимости: `requests`, `pandas`, `matplotlib`;
- группа `test`: `pytest`;
- группа `dev`: `ruff`.

Фрагмент `pyproject.toml`:

```toml
[project]
requires-python = ">=3.12,<3.13"
dependencies = [
    "requests (>=2.34.2,<3.0.0)",
    "pandas (>=3.0.6,<4.0.0)",
    "matplotlib (>=3.11.2,<4.0.0)"
]

[dependency-groups]
test = [
    "pytest (>=9.1.1,<10.0.0)"
]
dev = [
    "ruff (>=0.16.9,<0.17.0)"
]
```

Дерево зависимостей было получено с помощью:

```bash
poetry show --tree
```

Примеры транзитивных зависимостей основных пакетов:

- `requests` → `urllib3`;
- `pandas` → `numpy`;
- `matplotlib` → `contourpy`.

Точные версии полного графа зависимостей сохраняются в `poetry.lock`.

### Доработка программы

Скрипт `plt_temp.py` был доработан. Были выполнены следующие изменения:

- в HTTP-запрос добавлен параметр `timeout=15`;
- перед обработкой JSON вызывается `response.raise_for_status()`;
- преобразование данных вынесено в функцию `make_temperature_dataframe()`;
- CSV по-прежнему сохраняется в `temperature_24h.csv`;
- график сохраняется в `temperature_24h.png`.

Функция `make_temperature_dataframe()` получает списки времени и температур через аргументы и не выполняет сетевых запросов. Поэтому её можно тестировать отдельно от внешнего API.

### Точечное обновление зависимости

Перед точечным обновлением исходные файлы `pyproject.toml` и `poetry.lock` были зафиксированы в Git.

Для обновления была выбрана прямая зависимость `requests`, для которой задан диапазон:

```toml
"requests (>=2.34.2,<3.0.0)"
```

Были выполнены команды:

```bash
poetry show --outdated
poetry show requests
poetry update requests
poetry show requests
git diff -- pyproject.toml poetry.lock
```

Версия `requests` до и после команды обновления осталась `2.34.2`. Poetry вывел:

```text
No dependencies to install or update
```

Команда `git diff -- pyproject.toml poetry.lock` не показала различий. Это значит, что `pyproject.toml`, `poetry.lock` и транзитивные зависимости не изменились, так как более новой совместимой версии на момент проверки не было найдено.

Диапазон `>=2.34.2,<3.0.0` позволяет получать совместимые обновления внутри ветки 2.x, но не позволяет установить следующую мажорную версию 3.x.

## Сравнение venv + pip и Poetry

Подход `venv + pip` использует отдельные инструменты. `venv` создаёт изолированное окружение, `pip` устанавливает зависимости, а файл `requirements.txt`, созданный через `pip freeze`, фиксирует точные версии прямых и транзитивных пакетов. Восстановление выполняется командой:

```bash
python -m pip install -r requirements.txt
```

Poetry объединяет управление зависимостями, виртуальными окружениями и lock-файлом. В `pyproject.toml` описываются прямые зависимости, диапазоны версий и группы зависимостей. В `poetry.lock` фиксируются конкретные версии полного дерева зависимостей. Восстановление окружения выполняется командой:

```bash
poetry install
```

Poetry удобнее для проектов, в которых необходимо разделять зависимости программы, тестов и инструментов разработки. В данной работе `pytest` был добавлен в группу `test`, а `ruff` — в группу `dev`. Благодаря этому можно устанавливать только необходимый набор пакетов.

## Вывод

В ходе практической работы были созданы два независимых проекта на Python 3.12.14.

В первой части был освоен подход `venv + pip`: создание окружения, установка библиотек, фиксация версий в `requirements.txt` и восстановление после удаления `.venv`.

Во второй части был настроен Poetry-проект с локальным виртуальным окружением, ограничением версии Python, lock-файлом и раздельными группами зависимостей. Исходный скрипт был доработан: добавлены таймаут HTTP-запроса, проверка HTTP-ответа, сохранение графика и функция для преобразования данных, которую можно тестировать без сети. Были добавлены автоматический тест и проверка Ruff.

Оба подхода позволяют получить воспроизводимое окружение. При этом Poetry дополнительно упрощает работу с группами зависимостей и поддерживает согласованность между `pyproject.toml` и `poetry.lock`.

Эти инструменты полезны при создании серьезных проекто, однако в случае учебной деятельности где необходимо открывать разные проекты в одних и тех же окружениях удобнее использовать minicondа, создав под однотипные задачи отдельное глобальное окружение под определеные направления программирование, будь то обработка естественного язука, работа с геоданными и т д.
